# DREEM Helm chart

Installs DREEM on the management cluster:

| Component | Enabled by | Contents |
|---|---|---|
| CRDs | `crds.install` (default `true`) | `ClusterConfiguration`, `NodeSelecting`, `NodeHandling` |
| Operator | always | Deployment, ServiceAccount, manager ClusterRole, leader-election Role, metrics Service and roles (`operator.metrics.enabled`) |
| Configuration | always | ConfigMaps `cluster-configuration-parameters`, `forecast-parameters`, `selection-weights-scale-up`, `selection-weights-scale-down`; optional `bmc-credentials-<node>` Secrets |
| Forecaster | `forecast.enabled` (default `true`) | Deployment, ServiceAccount, Role and ClusterRole |
| metricUpdate | `metricUpdate.enabled` (default `false`) | CronJob, ServiceAccount, ClusterRole |

## Install

The operator and the forecaster look up their resources in the `dreem` namespace, so the chart refuses to install anywhere else.

```sh
helm install dreem deploy/helm/dreem-k8s -n dreem --create-namespace \
  --kubeconfig $MANAGEMENT_KUBECONFIG
```

Override the configuration with `--set` or a values file:

```sh
helm upgrade --install dreem deploy/helm/dreem-k8s -n dreem --create-namespace \
  --set config.clusterConfiguration.selectionProfile=QOS \
  --set metricUpdate.enabled=true \
  -f my-values.yaml
```

Keep BMC passwords out of `values.yaml`: put `config.bmcCredentials` in a separate, untracked values file, or create the `bmc-credentials-<node>` Secrets yourself.

Changes to the ConfigMaps don't need a restart: the forecaster and the operator re-read them on every cycle.

## Keeping the chart in sync with the operator

The CRDs and the manager ClusterRole are generated by controller-gen. After changing the API types or the `+kubebuilder:rbac` markers, run:

```sh
cd operators && make helm-sync
```

This regenerates the manifests and copies them into `files/`, from where the chart renders them.

## Uninstall

```sh
helm uninstall dreem -n dreem
```

With `crds.keep: true` (the default) the CRDs, and every custom resource they hold, stay in the cluster. Delete them with `kubectl delete crd clusterconfigurations.cluster.dreemk8s nodeselectings.cluster.dreemk8s nodehandlings.cluster.dreemk8s` if you really want them gone.
